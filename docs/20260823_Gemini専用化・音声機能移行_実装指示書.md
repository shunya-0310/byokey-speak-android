# BYOKey Speak Android: Gemini専用化・音声機能移行 実装指示書

更新日: 2026-08-23
対象リポジトリ: `D:\ドキュメント\Codex\byokey-speak-android`
対象ブランチ: `main`
目的: Play公開前に、Android版をGemini専用のlocal-first BYOK英会話アプリへ移行し、PWA版で確定したGemini TTSと音声会話操作を安全に反映する。

## 0. 結論と公開前ゲート

この移行は技術的には実装可能である。Gemini 3.1 Flash TTS Previewは、`/v1beta/interactions` のストリーミング応答と `AudioTrack` を使い、Android端末から直接再生できる。

公開前に、次の二点の運用判断を反映すること。一般消費者向けBYOKアプリとしての公開リスクは、公開責任者が認識したうえで、クライアント側キーの注意、明示同意、ソース公開、local-first設計を採るものとする。この対策はGemini規約への適合を保証するものではないが、本実装の公開判断を停止させる条件にはしない。

| 判断事項 | なぜ必要か | 本指示書の実装方針 |
| --- | --- | --- |
| 18歳未満のアクセス | 2026-03-23発効のGemini API追加規約は、18歳未満の個人向け、または18歳未満がアクセスする可能性のあるアプリでの本サービス利用を禁じている。 | Play Consoleで対象年齢を「18歳以上のみ」とし、[未成年によるアクセスを制限]を有効化する。さらに初回案内と更新同意で18歳以上確認を必須にし、確認前はGemini会話・Gemini TTSを実行不可にする。 |
| Gemini音声見本の同梱 | Gemini固有の追加規約は、生成コンテンツの所有権をGoogleが主張せず、利用者の裁量での使用と、その利用への責任を定めている。 | PWAで作成済みの固定WAV見本をAndroid APKへコピーして同梱する。見本は音声選択時だけローカル再生し、ユーザーのAPIキーやAPI呼び出しを使わない。生成モデル・固定文・生成日をリポジトリ内のasset manifestへ記録する。 |

上記は機能上の不具合ではなく、公開製品の運用判断である。既存PWAの扱いを遡って断定するものではない。Gemini TTS自体はPreview機能であるため、モデル廃止・応答形式変更・レート制限に備え、固定モデル名を一箇所に集約し、失敗時に別のAPIを自動実行しない。


## 1. 完成条件

### 1.1 プロダクト仕様

- 会話プロバイダーはGoogle Geminiのみとする。OpenAIとAnthropicの選択肢、通信処理、案内、文書、テストは削除する。
- 会話用の既定モデルは `gemini-3.1-flash-lite` とする。会話モデル選択はGeminiの許可リストだけを表示する。
- 読み上げ方式は「端末の音声」と「Gemini音声（API利用）」の二択とする。
- Gemini音声は `gemini-3.1-flash-tts-preview` に固定し、会話モデル選択とは分離する。Gemini Liveは追加しない。
- 30種類のGemini音声を選択できる。読み上げ方式をGeminiに切り替えただけでは音を出さない。
- `Voice (Gemini) ※選択時に音声が再生されます` と表示し、声の選択時に同梱済みのローカルWAVを再生する。見本再生ではAPIを呼ばない。
- 音声入力中の独自オーバーレイは作らない。既存のAndroid標準音声認識画面をそのまま使う。
- 会話のヘッドフォンボタンは二状態だけとする。
  - OFF
  - `読み上げ&マイクオート`（コーチ返信の再生完了後に英語マイクを起動）
- `フルオート` は削除する。認識終了後に無条件で送信する処理は存在してはならない。
- GitHubのAndroidソースへのリンクをAboutに追加する。

### 1.2 Local-firstと外部送信の契約

- APIキーは既存どおりAndroid Keystore保護のAES-GCM暗号化保存とし、バックアップ・ログ・共有・Gitには含めない。
- 会話生成時は、会話本文・コーチ設定・CEFR設定・必要な会話文脈をGemini APIへ直接送る。
- Gemini音声を選択した時だけ、読み上げ対象のコーチ返信をGemini APIへ直接送る。端末音声ではこの送信を行わない。
- BYOKey Labのサーバーは会話・TTS・APIキーを経由または保存しない。既存のAI回答報告を利用者が明示送信する場合だけは、その報告エンドポイントが例外であることを、アプリ・サイト・Data safetyへ正確に記載する。
- 生成済みTTS音声キャッシュは端末内のアプリ専用領域にのみ置き、バックアップ対象外・上限付き・削除可能にする。

## 3. Gemini専用化と既存ユーザー移行

### 3.1 対象ファイル

- `app/src/main/java/com/byokeylab/speak/AppStorage.kt`

- `app/src/main/java/com/byokeylab/speak/ui/SettingsScreen.kt`
- `app/src/main/java/com/byokeylab/speak/AppViewModel.kt`

### 3.2 モデルと設定

1. `LlmProvider`のOpenAI・Anthropic列挙値とそのモデル候補を削除する。将来のprovider再追加余地のために空のprovider抽象化を残す必要はない。Geminiのみの定数へ単純化する。
2. 会話用モデルはGeminiの許可リストのみとし、既定値を `gemini-3.1-flash-lite` にする。
3. `AppSettings`に次を追加する。

```kotlin
enum class SpeechOutputProvider { Device, Gemini }

enum class GeminiTtsVoice(val apiName: String, val label: String, val style: String) {
    Kore("Kore", "Kore", "Firm"),
    // Google公式の全30音声を列挙する。
}
```

4. `voiceGender`は端末音声を選んだ場合だけに使用する。`SpeechOutputProvider.Gemini`時にFemale/MaleをGemini音声の性別として扱ってはならない。
5. TTSモデル名・endpoint・PCM既定仕様は専用の`GeminiTtsConfig`へ集約する。画面やViewModelに文字列を散在させない。

```kotlin
const val MODEL = "gemini-3.1-flash-tts-preview"
const val ENDPOINT = "https://generativelanguage.googleapis.com/v1beta/interactions"
const val API_REVISION = "2026-05-20"
const val DEFAULT_SAMPLE_RATE_HZ = 24_000
```

### 3.3 必須の設定移行

現行アプリは、選択プロバイダーを問わず同じ安全領域にAPIキーを一件だけ保存する。そのため、OpenAIまたはAnthropicを選んでいた既存利用者をGemini固定にするだけでは、別社のキーをGoogleへ送ってしまう危険がある。

以下を必ず実装する。

1. SharedPreferencesに一回限りの`gemini_only_migration_version`を設ける。
2. `LlmProvider`をparseする**前に**、SharedPreferencesの旧`provider`文字列をそのまま読み取る。先にenumからOpenAI／Anthropicを削除すると、旧値の意味を失うためである。
3. 過去providerがGemini以外なら、暗号化キー値を`SecureApiKeyStore`から削除する。
4. providerをGemini、会話モデルを許可リスト内の既定値に正規化する。
5. 過去providerがGeminiなら、既存Geminiキーは保持する。モデルが許可リスト外なら既定値へ正規化する。
6. 会話、Vocabulary List、進捗、コーチ設定、テーマ、バックアップデータは削除・初期化しない。
7. Gemini以外のキーを削除した利用者には、最初のSettings表示時に一度だけ次を通知する。

> Gemini専用化に伴い、以前のAPIキーをこの端末から削除しました。Gemini APIキーを設定してください。会話履歴や学習データは保持されています。

8. 移行済みversionを保存して再表示・再削除を防ぐ。

### 3.4 バックアップ互換

- 新しい`PortableSettings`から`provider`を除く。APIキーは従来どおり絶対に含めない。
- 既存形式のバックアップ復元時は、旧provider文字列を読めてもGeminiとして正規化し、APIキーを復元しない。
- `speechOutputProvider`、`geminiTtsVoice`、端末音声速度を新形式の非秘密設定として追加する。
- 旧バックアップに新設定がない場合は、`Device`と既定音声を使う。
- バックアップの復元失敗時は、既存データを一切変更しない。

### 3.5 LLM通信の整理

- `LlmClient.generateDetailed()`の分岐をGemini専用にする。
- `generateWithOpenAi()`、`generateWithAnthropic()`、各社固有のURL・HTTPヘッダー・エラー文・テストを削除する。
- UI、Help、README、プライバシー、Play申告、ストア説明のOpenAI/Claude表記を残さない。

## 4. Gemini TTSの実装

### 4.1 方式

`GeminiTtsClient`と`GeminiTtsPlayer`を新設し、UI・ViewModel・HTTP・PCM再生の責務を分離する。

- HTTP: `OkHttp`で`POST /v1beta/interactions`。
- 認証: 利用者がKeystore保護領域に保存したGemini APIキーを`x-goog-api-key`へだけ付与する。
- リクエスト: `response_format.type = "audio"`、`generation_config.speech_config = [{ voice: <選択名> }]`、`stream = true`。
- ヘッダー: `Content-Type: application/json`、`Api-Revision: 2026-05-20`。
- 再生: `step.delta`かつ`delta.type == "audio"`のBase64 PCMチャンクを順に`AudioTrack`へ投入する。
- キャンセル: 停止ボタン、画面破棄、別メッセージ再生開始、ViewModel破棄のすべてでHTTP Call・コルーチン・`AudioTrack`を停止／解放する。
- Audio Focus: 一時的なmedia利用として取得し、完了・失敗・停止の全経路で解放する。電話等でfocusを失った場合は再生を停止し、勝手にマイクを起動しない。

リクエスト形は次とする。キー値はコード、ログ、テストfixtureに書かない。

```json
{
  "model": "gemini-3.1-flash-tts-preview",
  "input": "<コーチ返信本文>",
  "response_format": { "type": "audio" },
  "generation_config": {
    "speech_config": [{ "voice": "Kore" }]
  },
  "stream": true
}
```

### 4.2 失敗・再送・課金の扱い

- Gemini音声に端末音声への自動フォールバックは設けない。利用者が設定で端末音声を選び直す。
- タイムアウト、HTTP 4xx/5xx、SSE形式不正、音声チャンク0件、PCM再生失敗は区別して短い日本語エラーを表示する。
- エラー時に黙って同じTTSリクエストを再送してはならない。再試行は利用者の明示操作だけにする。
- 生成途中で停止した場合、取得済みチャンクを再生するかを実装者判断に委ねない。今回は「停止＝即停止、再生完了扱いにしない」とする。
- 返信本文はTTSへ渡す前に空文字を除外し、製品上限を設ける。上限超過時は文章を文境界で分割するか、読み上げ対象外として明示する。途中で切り捨てて内容を黙って失わせない。
- Gemini 3.1 Flash TTSはPreviewであるため、モデル利用不可時にモデル名を隠して曖昧なエラーにせず、設定・ヘルプから確認できる表示にする。

### 4.3 再生キャッシュ

同じ返信を停止後に再生し直すたび、再度Gemini APIを呼んで課金しない。

1. キーは`messageId + TTSモデル名 + Gemini音声名 + 本文SHA-256`とする。
2. 音声本体はアプリ専用の`filesDir/generated_tts/`に置く。Roomへ巨大なBLOBを保存しない。
3. Roomまたは小さいmetadata storeに、ファイル名・サイズ・最終利用時刻・仕様を保存する。
4. 最大容量は実装時に20 MBを初期値として設定し、上限を超えたら最終利用日時が古いものから削除する。設定画面の「全ローカルデータ削除」では必ず削除する。
5. バックアップ・共有・クラウドバックアップにキャッシュを含めない。
6. キャッシュの破損・ファイル欠落時だけ、利用者が再生を押した場合に新規生成する。

### 4.5 音声見本の扱い

- PWAの`public/voice-previews`にある生成済みWAVの原本と、生成時モデル・生成日時を確認する。
- Androidの`app/src/main/res/raw/`へ、正規化済みのWAVをコピーする。ファイル名は小文字とアンダースコアだけにする。
- 見本の文は固定し、APIリクエストを発生させない。
- Gemini音声の選択時だけ`SoundPool`または`MediaPlayer`で一回再生する。読み上げ方式を切り替えた時、画面を開いた時、復元時には自動再生しない。

## 5. 会話画面と音声モード

### 5.1 対象ファイル

- `app/src/main/java/com/byokeylab/speak/Models.kt`
- `app/src/main/java/com/byokeylab/speak/MainActivity.kt`
- `app/src/main/java/com/byokeylab/speak/ui/ConversationUi.kt`

### 5.2 モードの置換

現行の`ConversationAutoMode.Off / ManualSend / FullAuto`を次へ置き換える。

```kotlin
enum class ConversationSpeechMode {
    Off,
    ReadAndMicAuto;

    fun next() = when (this) {
        Off -> ReadAndMicAuto
        ReadAndMicAuto -> Off
    }
}
```

- `FullAuto`、`ManualSend`、`→⇔`、フルオート説明文、認識結果の自動送信を完全に削除する。
- ヘッドフォンアイコンはOFF時に通常表示、`ReadAndMicAuto`時に右下へ`A`バッジを付ける。
- content descriptionとトーストは`読み上げ&マイクオート`とする。
- Composer上の説明文は次とする。

> ✦ 読み上げ&マイクオート: 返信を読み上げた後、英語マイクを自動で起動します。話し終えたら英語マイクを押して送信してください。

### 5.3 マイク起動条件

- コーチ返信が存在する。
- モードが`ReadAndMicAuto`である。
- その返信の再生が正常に最後まで完了した。
- 画面が会話画面として前面にあり、ユーザーが停止操作・画面戻る・再生方式変更をしていない。

上記を全て満たす時だけ、既存の`RecognizerIntent.ACTION_RECOGNIZE_SPEECH`を英語指定で起動する。TTS失敗、キャンセル、focus喪失、端末音声エンジン失敗、Geminiストリーム失敗では絶対に起動しない。

Android標準の認識画面を使うため、PWA版のような独自の録音中オーバーレイは実装しない。

## 7. 初回案内と再同意

対象: `app/src/main/java/com/byokeylab/speak/ui/OnboardingScreen.kt`、`AppStorage.kt`、`AppViewModel.kt`

### 7.1 既存同意の更新

Gemini専用化とGemini TTS追加は、外部送信先・送信目的の説明を変える。既存の同意を流用せず、`external_data_consent_version`を引き上げる。

- 新規利用者: 最終ページのチェックボックスを有効にするまで完了不可。
- 既存利用者: 初回の会話送信またはGemini TTS実行前に、更新された同意ダイアログを必ず表示する。
- 同意しない場合: 設定・ローカル閲覧・バックアップは可能、Gemini会話とGemini音声はブロックする。
- 同意日時と同意versionを端末内へ保存する。APIキーや会話本文は同意記録へ書かない。

### 7.2 ページ構成と文言要件

文章は端末幅で自然に改行される短い段落にする。技術用語を先に説明せず、利用者の行動と影響を先に書く。

1. **BYOKey Speakへようこそ**
   - Geminiを使う英会話ブラウザではなく、Androidアプリであることを自然な言葉で説明する。
   - 自分専属のコーチ像を自由に設定できること、CEFR A1〜C2を選べることを説明する。
2. **BYOKとGemini API**
   - BYOKは自分のAPIキーを使う方式であること。
   - Googleアカウントでキーを作成でき、使用量に応じて料金が発生すること。
   - アプリ代金とAPI利用料は別であること。
   - 会話は端末からGemini APIへ直接送られ、BYOKey Labの会話・TTSサーバーを経由しないこと。
   - BYOKey LabがAPIキーを取得・保存・照会しないこと。
3. **APIキーの安全な扱い**
   - キーはGemini利用権限に結び付く重要情報であること。
   - 専用キー、Google Cloud側の予算／上限、利用量確認、定期更新を勧める。
   - Android Keystoreによる暗号化保存は偶発的露出を減らすが、侵害端末からの完全な保護を保証しないこと。
4. **データとバックアップ**
   - 会話、Vocabulary List、進捗、コーチ設定は端末内に保存されること。
   - アンインストール、アプリストレージ削除、端末故障で失われ得ること。
   - アプリ内バックアップ／復元が可能であること、APIキーはバックアップされず新端末で再入力が必要なこと。
   - Gemini音声を選んだ時は、コーチ返信の本文もGemini APIへ送られること。端末音声では送られないこと。
5. **さあ、はじめましょう**
   - Gemini APIキー、会話モデル、CEFR、コーチ、読み上げ方式をSettingsで選ぶ案内。
   - 18歳以上であること、およびGeminiへの外部送信・API利用料・AI応答の限界を理解したことを確認するチェック。Play Consoleによる未成年アクセス制限を補完するアプリ内確認であり、確認前はGemini機能を実行できないようにする。
   - チェック文言例: `私は18歳以上であり、Gemini APIへの外部送信とAPI利用料、AI利用上の注意を理解しました。`

### 7.3 表記上の禁止

- OpenAI、Claude、複数プロバイダーの選択説明を残さない。
- 「完全に安全」「漏えいしない」「GoogleがモバイルでのAPIキー入力を推奨している」と断定しない。
- API利用料を固定額・月額と断定しない。
- Gemini TTSを選んだ時に予告なく音声を鳴らさない。

### 8.3 Play Console

- 現在のバイナリと全SDKの通信を基準にData safetyを再回答する。直接Geminiへ送るデータも端末外送信である。
- AI生成コンテンツの報告導線は残し、実機で送信成功・失敗・キー非送信を確認する。
- App accessの審査用キー・手順はGeminiのみへ更新する。審査用キーをコミットしない。
- Play Consoleの`ポリシー > アプリのコンテンツ > ターゲット ユーザーおよびコンテンツ`で、対象年齢を`18歳以上のみ`にする。同画面の`未成年によるアクセスを制限`を有効にする。既にインストール済みの未成年利用者まではPlay側で排除できないため、アプリ更新後の再同意・年齢確認でもGemini機能をブロックする。
- IARC、ストア説明、オンボーディング、Privacy Policyを18歳以上向けという申告と矛盾させない。
- EEA・スイス・英国で利用可能にする場合、Gemini API追加規約に従い、利用者のCloud ProjectがPaid Servicesを使用することを案内する。地域を限定する場合もストア販売地域と説明を一致させる。
- モデルがPreviewであること、提供状況・料金・規約は公開直前に公式ページで再確認する。

## 9. テストと受け入れ基準

### 9.1 Unit / integration

- Gemini以外の旧providerで保存された設定からの移行: APIキーだけ削除、会話等は保持。
- Gemini旧設定からの移行: Geminiキー保持、非許可モデルを既定値へ正規化。
- 新旧バックアップの復元: APIキー非含有、旧providerをGeminiへ正規化、失敗時ロールバック。
- Gemini会話リクエストにOpenAI/ClaudeのURL・ヘッダーが混ざらない。
- Gemini TTSのJSONとヘッダー、Base64 PCM parser、チャンク0件、HTTPエラー、キャンセル、キャッシュhit/missをテスト。
- 同じmessage/voice/model本文ではキャッシュを使い、API呼び出しを増やさない。
- `ReadAndMicAuto`は正常再生完了時だけマイクを起動し、停止・失敗・focus喪失で起動しない。
- 認識終了後に自動送信しない。
- 更新同意がない時は会話／Gemini TTSをブロックする。

### 9.2 実機 smoke test

- 前バージョン（versionCode 8）から同じ署名で更新し、アンインストールなしでデータを維持する。
- 新規インストールでオンボーディング、18歳確認、APIキー未設定ブロック、Settingsへの遷移を確認する。
- Android標準音声入力の起動・取消・認識失敗・日本語／英語切替を確認する。
- 端末音声: 声別・速度別・停止・再生後のマイク自動起動を確認する。
- Gemini音声: Geminiキーで会話返信の再生、停止、再生し直しのキャッシュ、ネットワーク切断、429、無効キー、モデル利用不可を確認する。
- 画面回転、バックグラウンド復帰、電話／他アプリ音声のfocus喪失中に、TTSやマイクが暴走しないことを確認する。
- narrow phoneでSettings、オンボーディング、会話入力、bottom navigationの見切れをスクリーンショットで確認する。
- GitHub、Privacy、Terms、APIキーガイドの外部リンクをreleaseビルドで開く。

### 9.3 リリースビルド

1. `versionCode`を8より大きくする。`applicationId`と署名系統は変えない。
2. リリース候補を`testDebugUnitTest`、`assembleDebug`、`bundleRelease`で検証する。
3. AABのversionCode/name、SHA-256、サイズ、commit、ビルド日時、テスト結果を記録する。
4. Internal testingで旧版からの更新を確認後、Playの対象トラックへ提出する。
